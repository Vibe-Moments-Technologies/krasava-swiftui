отличие — в отличие от «Lite», которое намекает на урезанность и может читаться
как «неполная Красава». Плюс в подписи приложения название показывается целиком,
и «Krasava SwiftUI» хорошо смотрится рядом с основной «Красавой».

## 1. Резюме

Krasava SwiftUI — нативное приложение расписания РТУ МИРЭА для iOS 26, собранное
целиком на SwiftUI поверх системного Liquid Glass. Один основной экран
(мини-календарь + лента пар), набор нативных поверхностей (виджеты трёх групп,
Live Activity, Siri/Shortcuts, Spotlight) и никаких собственных сервисов.

В отличие от оригинала (Kotlin Multiplatform + Compose, ~40 экранов, игры,
карты, конспекты, задачи, сравнение расписаний), эта версия берёт **только то,
что относится к расписанию**, и доводит это до нативного качества iOS 26.

**Источник данных** — тот же, что у оригинала: два GET-эндпоинта
`schedule-of.mirea.ru`. Механики получения, кэширования, защиты от затирания
и типизации пар **переносятся как отлаженные** (см. §6) — они проверены
в бою оригинальным приложением.

**Про «сервисы».** Исключаются **свои сервисы Красавы** (Карты, Конспекты,
Задачи, Свободные аудитории, Ресурсы, Сравнение). **Нативные системные
возможности Apple — наоборот, используем по полной**: виджеты, Live Activity,
Siri, Shortcuts, Spotlight, Control Center, iCloud Backup.

## 4. Дизайн: Liquid Glass, системные цвета

### 4.1 Тема

| Режим | Реализация |
|---|---|
| **Системная** (по умолчанию) | `preferredColorScheme = nil` |
| Светлая | `.light` |
| Тёмная | `.dark` |

Никаких собственных палитр. Только семантические токены: `label`,
`secondaryLabel`, `separator`, `systemBackground`, `tint`.

### 4.2 Liquid Glass — API iOS 26

Используем **только системные примитивы**, без самодельного glass-эффекта:

```swift
// Контейнер: объединяет стеклянные формы, даёт морфинг и общий рендер
GlassEffectContainer(spacing: 24) {
    HStack(spacing: 16) {
        Button { … } label: { Image(systemName: "arrow.clockwise") }
            .buttonStyle(.glass)

        Button { … } label: { Text("Сегодня") }
            .buttonStyle(.glassProminent)
            .tint(.accentColor)
    }
}

// Стекло на произвольном элементе
Label("ИКБО-10-25", systemImage: "calendar")
    .padding(.horizontal, 14).padding(.vertical, 8)
    .glassEffect(.regular.interactive(), in: .capsule(style: .continuous))

// Морфинг «кнопка → панель»
.glassEffectID("today-bar", in: glassNamespace)
```

**Правила:**

1. Стекло — только на **управляющих слоях** (навигация, плавающая панель,
   шторки, капсулы выбора). Контент — на системном фоне.
2. **Никогда стекло-в-стекле.** Внутри стеклянной панели — только плоские
   элементы.
3. Не стеклить каждый элемент списка. Карточка пары — обычная поверхность.
4. Навигационная панель и таб-бар стеклянные **автоматически** — не
   переопределяем.
5. При `accessibilityReduceTransparency` и Increase Contrast — не форсим
   `glassEffect`, отдаём системе непрозрачный вариант.
6. `glassEffectID` + `Namespace` — для морфинга между состояниями
   (свёрнутый календарь ↔ раскрытый).

### 4.3 Типографика

Системный шрифт, Dynamic Type обязателен: `.font(.body)`, `.font(.headline)`.
Числа времени — `.monospacedDigit()`. Никаких фиксированных `size:` в обычном
тексте; пт-значения только в виджетах (там другая плотность).

## 6. Расписание: данные, кэш, парсинг

### 6.1 Источник

```
GET /schedule/api/search?match={q}&limit=50
GET /schedule/api/ical/{Group|Teacher|Auditorium}/{id}?includeMeta=true
```

Проверено 30.10.2026: сервер жив, `text/calendar; charset=utf-8`, ~100 КБ.
**ETag/Last-Modified/Cache-Control не отдаёт** — кэш только наш.

### 6.2 Что переносим из оригинала **без переизобретения**

Это отлаженные механики — переносим логику, а не код:

| Механика | Правило (как в оригинале) |
|---|---|
| Unfolding строк iCal | строка с ведущим пробелом приклеивается к предыдущей |
| Маркеры недель | `TRANSP:TRANSPARENT` + `SUMMARY` ~ `^(\d+)\s+недел`, `DTSTART` = понедельник |
| Номер недели | **источник истины — маркеры фида**; фолбэк — расчёт (9 фев / 1 сен), выровненный на понедельник |
| Раскрытие RRULE | `INTERVAL`, `UNTIL`, шаг = `7 × INTERVAL`; нет `UNTIL` → горизонт 5 месяцев |
| EXDATE | исключение по дате (время игнорируется) |
| Тип пары | сначала `X-META-FULL_LESSON_TYPE`, иначе аббревиатура `X-META-LESSON_TYPE` |
| Порядок проверок типа | «доп» **до** «пр» (иначе «доп. практика» → практика) |
| «СДО» | маркер дистанта, не аудитория |
| TTL кэша | 30 минут |
| Фон-рефреш | только когда приложение активно (энергосбережение) |
| Защита от затирания | пустой/битый ответ **не** перезаписывает кэш |
| Ошибка без кэша | полноэкранная ошибка + «Повторить» |
| Ошибка с кэшем | баннер, показываем кэш |
| Diff | ключ `дата | пара | предмет.lowercase()`; ADDED / MODIFIED / CANCELLED |

### 6.3 Модель для Lite

Отличие от оригинала: храним **Occurrence (RRULE + исключения)**, а не
развёрнутые даты на семестр. Слоты дня вычисляем из окна [−14, +90] дней.
Кэш компактный, а виджетам отдаём отдельный компактный снапшот (§10.4).

```swift
struct Occurrence: Codable, Hashable {
    let uid: String
    let subject: String
    let type: LessonType        // умный тип (§7)
    let teachers: [String]
    let rooms: [String]
    let groups: [String]
    let bell: Int
    let start: DateComponents   // час/минута
    let end: DateComponents
    let weekday: Int            // 1…7
    let interval: Int           // 1 или 2
    let until: Date
    let excluded: Set<String>   // yyyy-MM-dd
}
```

## 7. Гибридные типы занятий

Ключевое отличие от оригинала: тип занятия — не константа из фида, а
**гибрид**.

### 7.1 Определение (автоматическое)

1. По `X-META-FULL_LESSON_TYPE` («Лекции», «Практические занятия»,
   «Самостоятельная работа», …).
2. Если не распознано — по аббревиатуре `X-META-LESSON_TYPE`.
3. Если и это не вышло — `other` («Занятие»).

Ровно логика оригинала, чтобы новые/филиальные типы не ломались.

### 7.2 Переопределение (ручное)

Пользователь может:
- **сменить тип у пары** — «эта пара на самом деле лабораторная»;
- **сменить тип у всех пар предмета** — «у «Конфигурационного управления»
  все пары — практика»;
- **вернуть авто** — сброс к определённому из фида.

Иерархия: `override(конкретная пара) > override(предмет) > авто`.

### 7.3 Цвета

| Что | Как |
|---|---|
| Дефолтные цвета | свои для LIGHT и DARK, в духе оригинала (лекция — синяя, практика — зелёная, лаб — оранжевая, экзамен — красная, зачёт — бирюзовая, курсовая — жёлтая, консультация — индиго, самост. — серо-синяя, доп. — розовая) |
| Переопределение | у каждого из 10 типов можно выбрать цвет (системный `ColorPicker` с палитрой) |
| Где применяется | бейдж типа, акцентная полоса карточки, **точки в мини-календаре**, виджеты (через снапшот) |

Важно: дефолт подбираем так, чтобы он **совпадал с палитрой виджета**
(§10.5), иначе бейдж в приложении и виджете разойдутся.

## 8. Заметки — и исправленный баг стирания

### 8.1 Баг оригинала

В оригинале при обновлении расписания заметки пропадают. Причина — заметка
привязана к `lesson.id`, а `id` синтезируется как `"${uid}_$date"` и
**пересобирается при каждом parse**. Любое изменение `UID` в фиде (или его
отсутствие) даёт новый ключ → заметка «теряется». Плюс каскадное удаление
`removeNotesForTarget` при любых манипуляциях с целью.

### 8.2 Как делаем у нас — смена ключа

| Сущность | Ключ | Почему устойчив |
|---|---|---|
| Заметка к **паре** | `(targetId, yyyy-MM-dd, bell)` | пара однозначно определяется расписанием и номером; `UID` из фида **не участвует** |
| Заметка к **предмету** | `(targetId, subjectKey)` | `subjectKey` = нормализованное имя предмета (trim, lowercase, `ё→е`, схлопнутые пробелы) |

Дополнительно:
- Заметки хранятся **отдельным файлом** от кэша расписания — обновление
  фида физически не может их затронуть.
- При смене предмета у пары (редко) пара-заметка переезжает вместе с парой.
- Заметки к паре «переживают» смену типа и цвета.
- Удаление расписания спрашивает подтверждение и удаляет заметки — но
  **только** по явному действию, не каскадом при обновлении.

### 8.3 Нативная реализация (не как в оригинале)

Оригинал: отдельный экран в шите, «цветные поля». У нас — нативно:

- В карточке пары заметка показывается **превью-строкой** (2 строки, иконка
  `note.text`), если она есть.
- Правка — прямо в **экране деталей пары**, inline `TextField(axis: .vertical)`.
  Без промежуточных шитов.
- В экране деталей предмета — заметка к предмету в той же inline-манере.
- Автосохранение при уходе с экрана (`.onDisappear` + debounce 500 мс).
- Синхронизация через iCloud — **не делаем** (это сервис). Только локально
  + экспорт в буфер обмена по долгому нажатию.

## 9. Настройки: меню верхнего уровня

По решению владельца: **настройки, изменения и инфо — в верхнем меню**, а не
отдельным глубоким разделом. Меню `.menu` из нав. панели:

```
⚙️ ├─ Отображение…            → шторка
   ├─ Уведомления…             → шторка
   ├─ Типы и цвета…            → шторка
   ├─ Скрытые предметы…        → шторка
   ├─ Изменения в расписании   → шторка (diff, бейдж-счётчик, если есть)
   ├─ Обновить расписание      → действие
   ├─ О приложении             → шторка (версия, сборка, канал, источник, лицензия)
   └─ Поддержите проект        → ссылка
```

Плюс в самой нав. панели — отдельная кнопка **«Изменения»**, когда есть diff
(бейдж с количеством). Так владелец видит изменения без захода в меню.

### 9.1 Содержимое шторок

**Отображение** — тема (Системная/Светлая/Тёмная), пустые пары, сокращённые
названия, прокрутка к текущей паре, прогресс пары, прогресс перемены, свайп-
сворачивание календаря, две недели в календаре, размер виджета по умолчанию.

**Уведомления** — напоминать о парах, за сколько минут (5…60), тестовое
уведомление, **«Не напоминать о этой паре»** и **«Не напоминать о предмете»**
выставляются из деталей пары/предмета, а здесь — список исключений с
возможностью вернуть.

**Типы и цвета** — 10 типов, каждый: название, дефолтный бейдж, выбор цвета,
«сбросить». Плюс «Сбросить все цвета».

**Скрытые предметы** — список скрытых предметов с «вернуть». Скрытие
действует на: ленту, календарь, виджеты, уведомления, diff.

## 10. Виджеты

Порт виджетов оригинала: **та же логика, тот же набор функций, другой визуал**
(нативное стекло).

### 10.1 Набор

| Виджет | Семейства | Содержимое |
|---|---|---|
| **Расписание** | `.systemSmall`, `.systemMedium`, `.systemLarge`, `.systemExtraLarge` | главная (текущая/ближайшая) пара + следующие |
| **Календарь** | `.systemMedium`, `.systemLarge` | сетка недели/месяца с точками, расцветка типов (новый — дополнение к портрету) |
| **Lock Screen** | `.accessoryRectangular`, `.accessoryCircular`, `.accessoryInline` | текущая/следующая пара, прогресс кольцом |
| **StandBy** | `AccessoryWidget` в режиме «время» | крупно: пара, аудитория, время |

### 10.2 Логика (перенос из `ScheduleSelectionEngine`)

- Приоритет: **текущая пара → ближайшая предстоящая → первая пара ближайшего
  дня с занятиями**.
- Статусы: `current`, `soon` (≤ 30 мин до начала, включительно), `upcoming`.
- Прогресс идущей пары — 0…1, `nil` для будущей.
- Свежесть снапшота: `fresh` / `stale(hours:)` после 36 часов — показываем
  честную пометку.
- Пустые состояния **различаются**: `noTarget`, `noLessons`, `noData`,
  `badData`, `noGroupEntitlement` — по ТЗ оригинала это важно, повторяем.
- Заголовки дней: «СЕГОДНЯ · СРЕДА», «ПТ, 23 ОКТ» — но через `Locale`, а не
  хардкод `ru_RU` (это фикс при переходе на мультиязычность).

### 10.3 Timeline (перенос `WidgetTimelineBuilder`)

- Записи на границах: начало пары, конец пары, момент «СКОРО» (−30 мин),
  полуночи на 4 дня вперёд, шаги прогресса каждые 15 минут внутри идущей пары.
- Склейка записей ближе 30 секунд; потолок 64 записи.
- `policy: .atEnd`.

### 10.4 Данные

- Общий контейнер **App Group** (как в оригинале), запись в `UserDefaults`
  под ключом `widget_payload`.
- Пишем **компактный JSON на 7 дней вперёд**: `id, date, bell, start, end,
  subject, type, room, teacher, groups`.
- Пишет приложение при любом изменении кэша/цели/типов/скрытых.
- Виджет **никогда не ходит в сеть** — это важное правило оригинала,
  сохраняем.
- Определение App Group из подписи (`embedded.mobileprovision`) — сохраняем
  подход, он нужен для sideload-подписи.

### 10.5 Визуал — отличия от оригинала

Оригинал: графитовая поверхность с собственной палитрой.
Lite: **нативный системный виджет**.

| Было | Стало |
|---|---|
| Свой графит `#292C31` / `#F2F3F5` | `containerBackground(for: .widget)` с системным материалом |
| Своя палитра текста | `primary` / `secondary` семантические цвета |
| Свои акценты | `.widgetAccentable()` + tint |
| Свой бейдж типа | цвет типа, но через системный tint + `widgetAccentedRenderingMode` |
| Ручная работа с тонированием | `widgetRenderingMode` → всё, что не `.fullColor`, ставим акцентом |

То есть: **функционал один в один, кожа — системная**. Виджет должен
выглядеть как «родной» виджет Apple в iOS 26.

## 13. Версионирование и CI (наследуем оригинал)

### 13.1 Модель версий

Схема оригинала, адаптированная под один проект:

| Канал | Триггер | Формат версии | Release |
|---|---|---|---|
| **stable** | тег `v26.1.0` | `26.1.0` | `--latest`, иммутабельный |
| **beta** | тег `v26.1.0-beta.3` | `26.1.0-beta.3` | prerelease, иммутабельный |
| **rc** | тег `v26.1.0-rc.1` | `26.1.0-rc.1` | prerelease, иммутабельный |
| **dev** | push в `main` | `26.1.0-dev.N` | один rolling-релиз `preview` (файлы перезаписываются) |
| **contrib** | ручной запуск ветки | `26.1.0-contrib.N` | артефакт, без релиза |

`CFBundleVersion` = **epoch-секунды**, вычисляются **один раз** в resolve-джобе
и раздаются всем джобам (`BUILD_NUMBER`). Это важный урок оригинала: `github.run_id`
не влезает в Int32, а `github.run_started_at` в выражениях рендерится пустым.

### 13.2 Файлы

- Версия в репо живёт **только** в `AppVersion.swift` (`RELEASE_VERSION = "26.1.0"`).
- CI патчит `AppVersion.swift` + `Info.plist` (`CFBundleShortVersionString`,
  `CFBundleVersion`).
- Скрипт: `tools/versioning.py` с командами `resolve` / `prepare` — порт
  оригинала.

### 13.3 Workflows

```
.github/workflows/
├── build-release.yml   # тег v* → resolve → build → publish → feeds(gh-pages)
├── preview-main.yml    # push в main → rolling preview
├── pr-check.yml        # PR → только сборка + тесты (без релиза)
└── stale.yml           # обслуживание
```

Раннер: `runs-on: macos-26` (доступен как GA с февраля 2026, Xcode 26.x).
Сборка **без подписи** (`CODE_SIGNING_ALLOWED=NO`), ad-hoc подпись
с entitlements для App Group (как в оригинале — иначе виджет остаётся без
общего контейнера после sideload).

### 13.4 Артефакты

- `KrasavaLite.ipa` — unsigned, для sideload (AltStore / GBox / Sideloadly).
- `krasavalite.apps.json` — AltStore-совместимый источник.
- `version.json` — фид версий на `gh-pages`.
